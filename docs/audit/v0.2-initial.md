# AAMS v0.2 initial audit

Baseline commit `9111dab25d8d54d960d5dc5927bdad6b30d64c3a` from the v0.1.0 release.

## Confirmed recovery defect

**Severity: moderate.** The backup verification API accepted a recovered database with incomplete canonical provenance. On a temporary fixture, a formation without its link and a revision without any evidence links passed SQLite's structural and foreign-key checks. Exact reads correctly raised `StoreIntegrityError` in both cases, while `verify_integrity()` returned successfully. This could lead an operator to declare a restored file usable before a subsequent recall failed.

Reproduction: `PYTHONPATH=src python -m unittest discover -s tests -p test_audit_integrity.py -v`. Before the fix, both cases failed at the assertion that full verification rejects incomplete provenance. After the fix, full verification runs the same formation and revision decoders as exact reads in one snapshot. This adds no schema migration.

## Existing evidence and remaining work

| Area | Evidence and disposition |
| --- | --- |
| Scoped links and exact reads | The storage, belief, recall and MCP suites verify scoped references, read-only grants, and uniform unknown/out-of-scope response shapes. |
| Replay and temporal selection | The storage suite checks equal-content replay and divergent-content conflict. The belief and recall suites check concurrent revision conflicts, recorded versus effective time, and history after restart. |
| Recovery | The recovery suite tests interrupted commits, persisted commits, backup and restore, and broken references. SQLite integrity does not authenticate a file or prove the provenance is factually correct. |
| MCP launch and error boundary | The host controls the local launch grant. Existing tests cover forged tool parameters, invalid arguments and non-echo of a malformed frame marker. Frame allocation and other runtime limits belong to #16. |
| Collection enumeration | Recall applies scope and time before ranking. The inspected path enumerates a local scope and visits records individually. Measure scaling in #17. |
| Direct file changes | The deployment trusts processes with raw access to SQLite files. The audit did not establish comprehensive schema attestation, protection from direct file writes, or detection of all logically valid content changes. |
| Untested environments | Full-disk errors, power loss, live grant changes without relaunch, and non-Linux platforms remain outside measured coverage. |
