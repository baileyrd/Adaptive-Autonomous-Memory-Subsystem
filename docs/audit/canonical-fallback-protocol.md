# Disposable canonical fallback preregistration

Parent work: #124, PR #130, base `789811865cb9bc56fe58dd26a757853c600b9585`. This is a new deterministic recovery experiment. The archived #130 scorecard remains checkpoint-only 12/48, host-assisted journal 40/48, direct canonical heads 44/48.

## Freeze and comparison

Before running any arm, publish this protocol, the episode generator and the SHA-256 of the complete generated inputs, including expected actions. Use 14 specified families with two design and four held-out variants each, paired across three arms (28 + 56 cases per arm). The generator reuses #130’s grammar with a new seed. Verify record IDs, scopes, source identities, locators, task and checkpoint IDs across splits and against all #130 cases. Fixtures are author-visible and share mechanisms across splits. No claim of unseen real-world task families. Freeze the runner and tests in a second commit before first scoring. Publish protocol deviations and failed runs; retain the original pins.

- **Checkpoint** uses #130’s amended restore and deterministic action.
- **Fallback** first uses the same restore. A ready claim ends the request. After any rejection on an initially authorized request, discard the candidate and resolve a fresh host view for the original trusted task, scope and principal. Check grant before any new lookup. Use only current host heads, the original recorded/effective cutoffs and up to eight exact references. Suppress all unsuccessful canonical responses to uniform unavailable; public responses never include a fallback reason. An initially denied request ends immediately.
- **Canonical control** reads the final snapshot directly for the same request. It has no access to checkpoint content. Use the same 8,192-byte final result budget, deterministic action and fresh-process reader. The fresh snapshot differs in the between-attempt revocation family only, where initial restore rejects. A missing sidecar and a foreign envelope exercise independent fallback. Cache expiry/revocation leaves independently readable evidence eligible. Conflicting or time-invisible heads yield no state. Owners may receive checkpoint lifecycle detail only under the amended grant. Per-attempt status and read counts are trusted offline audit data.

## Frozen scoring and invalidation

Primary endpoint is paired difference in correct decisions, fallback minus checkpoint on all 56 held-out requests. Report gains and regressions and percentile interval from 2,000 equally weighted whole-family resamples (seed 0, ordered indices 50 and 1950). Also report outcomes per family, per split and per arm. Ground truth comes from latent completed steps and blocking constraints, with final access denial requiring abstention. The action oracle does not consume restored state or evidence. An unresolved contradiction or invisible head must abstain for safety, but is a missed physical next action. Count correct ready resumptions and correct required denials separately. Report invented progress, lost active constraints in returned states, unavailable active constraints, repeated completed steps, citation validity, disclosure and any newly wrong actions. Cost (elapsed decision time) is descriptive and cannot gate reporting.

Validate every returned citation independently against the fixture bytes, scope, provenance and both time bounds. Any denied or expired-cache disclosure, post-denial lookup, partial state, unsafe contradiction resolution, invalid citation, budget overflow or mutation invalidates the run. Compare preparer and post-reader SHA-256 for every DB and sidecar byte across reopen. Use SQLite read-only mode for decision connections. Record actual arm traces and hashes. No automatic writes, refresh, model calls, production APIs or deployment inference. A pass/fail claim of general cognitive benefit is outside this question.
