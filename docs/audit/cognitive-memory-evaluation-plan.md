# Offline cognitive-memory evaluation plan

Tracking: #115 workstreams B/C, #109 retrieval evaluation, #105 coordination. Status: **design, not executed neural or task-level results**. The [traceability audit](cognitive-memory-traceability.md) identifies existing mechanisms and missing capabilities. The approved #115 decision supersedes v1.0's cost-before-quality research ordering; historical v0.8/v0.9 outcomes remain unchanged.

## Research questions and scorecards

Report four independent scorecards, per arm and workload:

| Scorecard | Measures | Decision meaning |
| --- | --- | --- |
| Correctness / safety | Unauthorized or future evidence returned; citation digest/source validity; lineage overcount; injected instructions executed; unsupported canonical promotion; fallback validity. | A safety violation invalidates the affected experimental arm/run. Report the failure without leaking protected content. Never trade it for quality or cost. |
| Cognitive-memory utility | Independently scored task/decision success, historical correctness, unsupported assertions, abstention/calibration, repeated error, unseen-family transfer and restart continuity. | Required for claims of improved reasoning or learning. Retrieval gains alone do not satisfy it. |
| Retrieval effectiveness | Recall@3/@10, nDCG@3/@10, satisfied@3, citation precision, unique relevant IDs absent from guarded BM25, wins/losses and contradiction coverage. | Measures access to evidence, including dense candidate discovery; distinguish full discovery from reranking a lexical list. |
| Operational efficiency | Cold/warm p50/p95/p99 where sample size supports them; CPU, peak/current RSS, startup, database/index bytes, build/rebuild time and worker count. | Deployment feasibility. Retain ≤5 ms added p95 and ≤2× matched guarded peak RSS; a failure never suppresses offline quality. |

Each arm has independent fields: execution status (`completed`, `invalid_safety`, `invalid_artifact`, `failed`, `resource_exhausted`, `not_run`), measured quality, measured costs, cost-gate decision and deployment eligibility. Missing values are null with a reason, never zero or inferred failure/success. A fallback is not a measurement of the intended encoder: report actual route/status and invalidate unexpected fallback before drawing neural conclusions. Retain scheduled task counts and failures to prevent survivor-only reporting.

## Bounded retrieval experiment (#109)

1. **Freeze the run manifest before seeing results.** Record source/base/head/merge-test SHAs, model revision and model/tokenizer SHA-256, pooling/truncation/dimension/index-space specification, dataset URL/hash and parser, selected group/task IDs and their hashes, ranking parameters, scoring code, seeds, repetitions, hardware, package lock/freeze, timeouts and counts. Fail closed on mismatches. Keep gold labels outside encoder inputs. Retain no private user data; public synthetic/source artifacts stay in isolated disposable stores.
2. **Inventory prior exposure.** Existing SQuAD/SciFact results have already informed BM25, routers and #112. The three-article cost sample and small v0.4/v0.6 fixtures are development/safety controls, not independent test evidence. Replaying previously inspected held-out data is replication/exploration. Choose unused SQuAD article groups only after checking past selection manifests; if exposure cannot be established, mark it unknown and do not call that result confirmatory. Freeze newly authored semantic/episodic families separately from development families. Reserve unseen families and sources for confirmation before tuning anything.
3. **Workloads.** (a) SQuAD dev and training-source grouped replay; (b) SciFact cross-domain evidence retrieval; (c) separately labeled paraphrase/vocabulary-mismatch pairs with exact-match controls; (d) changed facts, valid/recorded-time distinctions, copied provenance, explicit contradiction, rare prior failure and interrupted episodic tasks. Insert same-ID cross-scope decoys, future evidence, absent targets, copied-source aliases and instruction-like payloads. Cases must preserve authoritative provenance and labels independent of model similarity.
4. **Arms.** Include BM25 lexical and guarded BM25; original pinned float BGE, BGE q8 and MiniLM L3 q8; static 8M/32M from #112 after its exact-head review; explicit hybrid, dense candidate generation and existing RRF/fusion where implemented. One encoder per independent versioned index. Do not invent an unimplemented arm. Reranking BM25 top-20 is a separate arm with its lexical candidate ceiling; it cannot demonstrate recovery of evidence outside that list. Reuse #113's ceiling audit as a negative/control result, not an executed neural judge.
5. **Execution budget.** First instrument a bounded development smoke set (maximum 3 scopes/30 records/24 queries per arm) for hashes, routing and safety, without using its quality to tune confirmatory parameters. Then cap the initial exploratory public run at 24 SQuAD article groups, 10 questions per group, and 128 SciFact claims selected by frozen stable IDs. Record actual fewer counts instead of replacement sampling. Use a single worker, one arm/process at a time, Linux runner with at least 7 GiB RAM, 2 GiB per-child address-space ceiling where runtime compatible, 30 minutes per arm/workload and a 4-hour total job ceiling. A runtime incompatible with the memory limit is `resource_exhausted`/`failed`, not poor quality. Inspect baseline footprint before setting a hard limit; record any preregistered revision before candidate scoring. Use separate jobs if necessary, but compare costs only with a guarded comparator on that same host. Do not dynamically choose only promising arms after seeing quality or cost.
6. **Measure quality regardless of operational gate outcome.** The runner must not read a `qualifies` cost field to skip quality. Bound expensive runs using the explicit execution budget, and report every skipped/failed arm with reason. Cache only under pinned model+scope+time+digest keys and disclose cache reuse. Reopen/rebuild indexes through canonical authorization, freshness and integrity checks. Scope/time/provenance failures invalidate the run rather than being repaired by hiding bad rows.
7. **Statistics.** Score paired identical queries. Report arm totals, unique recovered relevant evidence and negative regressions by family. Bootstrap paired deltas over article groups for SQuAD, linked claim/evidence-document clusters for SciFact, and episode families for synthetic tasks; use 2,000 resamples and seed 0. Report 95% intervals with group counts, degenerate intervals and small-sample limitations. Query repetitions measure timing variation and are not independent quality samples. Keep exploratory multiple-arm comparisons descriptive; use a separate untouched confirmation set for a benefit claim. Freeze any quantitative utility threshold from baseline distributions before confirmation, rather than choosing it after results.
8. **Costs and Pareto report.** Reuse pinned #114/v0.9 process measurements with matched inputs/hardware and separate build/serve peaks. Capture process-cold first request plus repeated cold starts before quoting a cold p95; OS-cache-cold is a separate untested condition unless deliberately measured. Use 5 warm passes for initial cost sampling. A p99 from too few starts is `not_estimated`. Quality and RSS/latency must remain visible even when no arm is deployment-eligible. Display a Pareto table per workload, annotate uncertainty, safety invalidity and unmatched hardware; do not pool absolute costs across hosts.

### Existing commands and required runner work

These baseline commands already execute on main without model downloads:

```sh
python scripts/evaluate_learning.py --repetitions 30
python scripts/offline_experiment.py --split all --ranking bm25 --repetitions 5
```

The existing public harnesses are `scripts/evaluate_retrieval.py`, `scripts/evaluate_scifact.py`, and `scripts/offline_experiment.py`. Their `--encoder-dir` paths load the original BGE recipe through `fusion.open_encoder`; the main CLI does **not** yet select every quantized/static variant. Workstream B must add/test that plumbing or explicitly mark those arms unexecuted. Preserve existing `InvalidRun`/route checks and scoped citation filtering. Recall@10, unique recovered evidence, citation validation and new episodic/injection metrics require explicit additions where absent. Do not label the existing harness a complete implementation of this plan.

Keep the new quality workflow manually dispatched or otherwise explicitly optional, with no optional packages/model downloads in default CI. Prepare artifacts using the existing committed pins (`onnx_pins.json`, `onnx_variant_pins.json`, #112 static pins), verify them before optional imports and index mutation, and bound download size/time. A fresh external model or dataset needs an independent pinning step before it enters a measured run. No live neural service or external judge is required by this plan.

## Decision/outcome experiment (workstream C)

This is a separate benchmark from retrieval. First freeze a small development corpus of 12 episode families, each with a prior event, decision, independently generated outcome and a related transfer task; reserve 12 different families for confirmation. Use fixture-generating seed 0, publish fixture hashes and oracle decision rules, and blind scored outcome/transfer labels from retrieval and any model prompt. Repetitions over a deterministic episode do not increase independent sample size. Size a larger confirmatory set only after development baseline distributions are available; this small pilot cannot establish general learning.

Compare **no memory**, **raw source search**, and **current structured memory** on identical tasks with equal context/token budgets, tools and frozen decision policy/model. Add an experimental neural-assisted arm only after its safety protocol is implemented, without requiring a cost pass. When a model is used, pin prompts/decoding/seed/revision and record actual nondeterminism. Programmatic oracle decisions test a bounded task mechanism and must not be described as improved AI reasoning without a model/agent outcome study. Do not fabricate a no-memory answer or infer counterfactual outcomes from one observational log.

| Family / ablation | Independent ground truth | Task-level measures and expected failure signal |
| --- | --- | --- |
| Historical changed fact | Time-indexed event ledger and decision deadline, separate recorded/valid clocks. | Historical decision correctness; future-data leakage; compare latest-summary versus as-of reconstruction (H3). |
| Contradictory sources / copied reports | Frozen source dependencies and conflict labels, including shared origin. | Correct conclusion or justified abstention, unsupported certainty and provenance overcount; with/without contradiction packet (H2). |
| Rare-but-critical prior failure | Outcome from a deterministic external task simulator, independent of the agent's claim. | Repeated error and changed-decision benefit on a later unseen condition (H1). |
| Reviewed consolidation transfer | Original support/refutation ledger, separate reviewer and held-out task family. | Success and negative transfer versus raw episodes; lineage distortion; no unauthorized promotion (H4). |
| Restart / model replacement | Immutable task constraints, completed/pending steps and explicit expiry. | Lost constraints, invented progress and reconstruction cost; transcript replay versus checkpoint. Current checkpoint arm is **not implemented**, so mark it `not_run` until FR-009 lands (H6). |
| Authorized collective memory | Explicit sharing grants, private decoys and common-source dependencies. | Coordination success, scope leakage and correlated errors. Sharing arm `not_run` until FR-013 exists (H7). |

Persist decisions and independently grounded outcomes separately using the existing outcome contracts when their candidate linkage applies; do not misrepresent a generic task as a consolidation candidate merely to fit a schema. Identify any missing task-episode schema as a bounded follow-up. Evaluate feedback-driven policy changes exclusively offline/shadow, with an unchanged serving baseline. Use paired episode-family resampling, disclose false confidence and abstention, and review negative cases before a benefit claim. Calibration is only meaningful for genuine probabilistic outputs and enough independently labeled samples; otherwise report `not_estimated`.
